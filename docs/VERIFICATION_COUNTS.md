# 验证次数

每个 11 位编号独立累计成功验证次数。拒绝结果不计数，网络重放不重复计数。相同编号可出现在多份印刷品上，因此次数属于编号，而不是某一件实物。

客户端为每次检测创建 `X-Verification-ID`，要求 20–100 个字母、数字、下划线或连字符。同一照片上传失败后重试时复用编号；收到有效回复后，下一次检测创建新编号。

| 响应字段 | 含义 |
| --- | --- |
| `verification_count` | 该编号本次成功验证的序号，从 1 开始 |
| `verification_id` | 请求编号 |
| `verified_at` | 首次记录该请求的 UTC 时间 |
| `verification_replayed` | 是否返回已保存的成功结果 |
| `counting_since` | 当前数据库开始计数的 UTC 时间 |

同一请求编号和图片哈希重放时返回缓存结果，跳过解码和增次；同一请求编号用于不同图片时返回 HTTP 409。

`ARROW_DB_PATH` 默认为 `/var/lib/arrow/verifications.sqlite3`。SQLite 使用 WAL、FULL 同步和事务，把编号增次与完整响应保存为一个原子操作。请求 ID 唯一约束及 `(digits, ordinal)` 唯一约束保护并发更新。

v5 数据目录为 `/opt/arrow/v5-data`，由容器用户 10001 写入。备份使用 SQLite backup API；替换容器时保留挂载。镜像和 Git 仓库不包含实时计数数据库，上传的照片也不写入数据库。

自动测试覆盖并发递增、并发重试、数据库重开、前导零、冲突、事务回滚和拒绝结果不计数。计数存储不可用时返回 503，不返回未持久化的成功序号。
